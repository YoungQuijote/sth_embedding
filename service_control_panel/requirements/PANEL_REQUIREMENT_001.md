# PANEL_REQUIREMENT_001 — 独立 Mock 服务控制台 V1

## 目标与边界
根据本次会话确认的需求，在已有 backend/frontend 下分别实现 Python 与 TypeScript 应用。以仓库内部管理与观测闭环为主，不要求 Grafana/Prometheus。UI 参考用户线框图，自行完善层级和交互。
mock 接口依赖以 [MOCK_REQUIREMENT_001](../../agent_mock_service/requirements/MOCK_REQUIREMENT_001.md) 为契约，已推送 main 供另一侧实现。本侧按契约完成假设开发；真实实现完成后再联调。

## 具体约定
- Linux 部署账户具备非交互提权权限；目标机基础依赖由用户准备。允许通过包源安装 Python 依赖，包安装失败不通过切换环境掩盖，不强制破坏系统 Python 的发行版保护。
- K8s 清单已经包含业务配置、节点约束和本地镜像策略；Panel 不搭建集群、不自动改写业务清单。镜像加载 SSH 目标必须与指定节点匹配。访问入口由用户配置。
- UI 中非200分类保留用户口径，不把所有非200都命名为异常。业务流量与健康探测/试调隔离。
- 单用户/管理员、单 Panel 进程为 V1 范围。暂不包含自动回滚、资源删除、自动扩容、升级、多用户权限和工单系统。
- 远端失败资源保留供排查，操作日志说明失败阶段；密钥、token 不进入任务日志或列表响应。
