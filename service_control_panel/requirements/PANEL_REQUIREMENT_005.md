# Docker 参数回填与免传包重新部署

## 目标

部署时填错启动命令或配置后，允许从原实例直接修正参数并重新部署，省去卸载、移除监测、重传镜像和登记实例的流程。

## 功能范围

- Panel 部署的 Docker 实例：原重启入口改为“重新部署实例”，复用新增实例表单并回填上次提交的参数。
- 固定实例名称、远程环境、部署方式、根目录、部署包和镜像身份；服务实例 ID 不变。
- 可编辑启动方式、ENTRYPOINT、CMD、容器端口、失败重启次数、环境变量、额外挂载、Docker argv 参数，以及服务连接中的暴露端口、访问方式、URL 和管理令牌。
- SQLite 保存上次提交的配置；已生效配置与上次提交配置区分，失败后仍可回填错误参数继续修正。令牌、额外环境变量沿用加密存储。
- 不上传、不加载镜像包，不重新安装依赖；复用远端不可变镜像 ID 和实例持久化目录，不从镜像仓库拉取替代版本。
- 对原容器、镜像和目录做归属/存在性检查；检查失败时报告原因。初次启动失败后，只要原镜像 ID 和持久化目录可用，也可修正后重新部署。
- 新容器替换旧容器后验证 `/ready` 与管理协议；失败尝试恢复原容器及生效配置。保留任务日志与恢复记录，中断后的下一次重部署或卸载先处理恢复记录。
- 固定属性由后端限制；校验输入、重复 URL/端口、实例进行中任务及过期配置版本，不仅依赖前端置灰。

## 边界

本轮实现 Docker 参数重部署。裸机、K8s 保留原重启流程，外部接入实例仍不能操作未知归属资源。修改端口时 URL 由用户同步修改；连接配置不会自动修改防火墙。容器切换有短暂中断，内存会话清空；数据目录保留，但不进行数据库快照回滚。原镜像或原目录被移除时不自动重新传包。
