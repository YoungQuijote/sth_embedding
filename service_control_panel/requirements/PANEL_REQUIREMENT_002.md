# Panel V1 部署体验与实例生命周期改进

## 背景与范围

承接用户 Docker 部署验收反馈，保持 Python 后端、TypeScript 前端及内置监控架构。对侧 `panel.v1` 已实现，本次使用真实 mock 实现联调，不新增 mock 接口要求。

## 需求与验收

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| R1 | SSH 主机 SHA256 指纹可选 | 不填可保存/登录；首次成功认证后记住指纹，后续变更报错；显式填写仍严格核对 |
| R2 | Docker 远端上传目录可配置 | 在用户指定根目录的实例 ID 子目录部署；上传前检查权限/空间，加载前另查 Docker 数据目录；权限或空间不足不传包 |
| R3 | 可配置 Docker 启动 | 支持标准入口、镜像默认入口、自定义 entrypoint/参数、环境变量、额外挂载及常见运行参数；默认 on-failure:3，0 关闭自动重启；可见启动失败诊断 |
| R4 | 移除监测与卸载分开 | 任意状态可移除 UI/监测，不触碰远端、不取消已有任务；卸载需明确确认，按资源归属回退部署，保留共享资源；失败时可见原因 |
| R5 | 接入已有实例 | 按部署方式、URL、管理 token 接入；验证 ready、panel.v1、接口发现；直连无须 SSH；支持监测、试调与数据回流 |
| R6 | 上传性能可观测、提前拒绝超限 | 选择文件即可提示上限；后端按请求头在读取文件体前拒绝超限，仍累计验证实际字节；区分两段传输及加载/启动阶段，展示字节、速度、耗时 |
| R7 | 裸机同类优化 | 使用同一目录配置、空间/权限检查和传输进度；源码展开大小计入预算；保留 conda > venv > 系统 Python 规则 |

## 行为边界

- 根目录默认沿用已有 `/opt/svc-panel`，实际资源仅放入唯一实例子目录。Linux/root 或非交互 sudo 约定不变。
- 空间检查是执行时的最低容量检查，不是磁盘配额预留。Docker 解压/依赖安装的最终大小可能高于包大小，实际磁盘满会记录失败。
- Docker 参数使用 JSON argv，不进行隐式 shell 拼接；生命周期相关的名称、主要端口、重启、网络和挂载由专用字段管理。Docker bridge 仍预留。
- 卸载删除该实例容器或 systemd 单元、上传包、配置以及实例目录内数据库/日志/trace。额外挂载、共享镜像和系统 Python 共享包保留。
- 新 K8s 资源添加归属标签，拒绝覆盖已有对象；卸载逐一校验归属。旧 K8s 实例未记录归属时拒绝自动删除，允许移除监测。PVC 的删除可能触发集群存储回收策略，卸载确认明确包含持久数据。
- 外部接入实例没有 Panel 运行资源所有权，只支持监测及管理 API；不自动猜容器名/进程名执行重启或卸载。
- 上传 HTTP 协议改为二进制流，前后端必须一起升级；默认部署包 2 GiB、清单 2 MiB，均可配置。2 MiB 不适用于镜像包。
- 删除监测采用逻辑隐藏，后台任务记录保留，不因迟到结果恢复 UI。重新接入视为外部实例，不恢复原部署资源管理权。
